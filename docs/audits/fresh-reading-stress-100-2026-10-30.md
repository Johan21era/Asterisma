# Fresh reading-estimator stress evaluation — 100 rounds

**Result: 100 fresh synthetic rounds completed; not validated for real readers.** This report supplements the earlier [partial report](final-reading-stress-2026-10-30.md), whose historical results are not replaced. Generated by `python3 tools/cde/write_fresh_100_report.py` (exit 0).

## What was requested and done

The owner requested 100 fresh rounds after the earlier attempt only rescored old predictions. We generated fresh cases using distinct deterministic seeds, invoked the Swift estimator for every new input, captured 100 rounds of freshly seeded demo personas, and saved the inputs, outcomes, predictions, grades, Xcode logs and result bundles; the tree was hashed into [the evidence archive](evidence/fresh-stress-evidence-archive-2026-10-31.md) and deleted on 2026-10-31.

Each round contains 9,914 main cases: 4,004 synthetic development cases, 5,604 synthetic holdout-labelled cases, 234 corpus-development cases, 64 corpus-evaluation cases, and eight adversarial cases. Thus 100 rounds contain 991,400 main cases. Each also contains 16 newly seeded demo-persona cases; those 1,600 cases use a separate elapsed-time target. Together that is 993,000 case predictions, not 993,000 independent people. The generators use previously designed scenario recipes; seeds are new, recipes and book sets are not.

The corpus covers all 149 stored package rows in every round, two generated cases per package. Some rows share content digests. Package scores are stored features: the Swift estimator does not receive the actual books or their text. The synthetic generator uses fictional page sizes, response effects and future reading times. It produces four target cases per synthetic reader plus controls. Package scores and generated targets are not measurements of real people.

**SKIPPED: independent manual grading of every result.** Code scored and mechanically checked all main-case predictions. A human-style inspection of three extreme cases is described below; it is not a substitute for independent hand grades. **SKIPPED: sequential stop-on-spike, recalibrate and restart.** The model was frozen throughout, and scoring continued after spikes. Every round had at least one spike. **SKIPPED: real-reader and live-app accuracy validation**; actual interruptions, live page turns and storage reloads were not exercised.

## Method and frozen candidate

The app baseline is computed by the actual Swift `EstimationEngine` through the existing adversarial adapter. The experimental candidate blends that adapter’s recent and guarded predictions, using guarded weight 0.0011850789689659901 and recent weight 0.998814921031034. This weight was selected on previously inspected development cases before these fresh rounds; it was not retuned against these outcomes. It is not a production formula change. The same weight and candidate logic were used for all fresh rounds.

Rounds use seeds 86,000,000 + 100 × round plus fixed offsets for their independent generator calls. Identifiers are opaque hashes. Future outcomes were not supplied to the Swift estimator. Cases were scored after predictions were obtained; all rounds used the same generator families and fixed split definitions, so these are not independently designed blind tests. The four synthetic controls repeat the same design each round; randomized synthetic histories and outcomes use new seeds.

The demo test generates a fresh library with the persona’s normal generator and a per-round simulation seed. For one eligible book, it withholds the last 40 closed page timings and estimates using only timings closed by the first withheld timing. The held-back sum is **generated elapsed time over 40 visits**, not measured active time or necessarily 40 distinct remaining pages. Demo results are therefore reported separately. The detailed attachment contains every demo input and the withheld durations.

Absolute percentage error is `100 × |prediction − synthetic target| / synthetic target`. A spike is an absolute error greater than both 300 seconds and 75% of the synthetic target. This is an investigation rule, not a validated pass/fail threshold. The 90th percentile is the sorted value at Python index `round((n − 1) × 0.9)`. Percentages are rounded in this report; full precision is preserved as a compressed summary in [the evidence archive](evidence/fresh-stress-evidence-archive-2026-10-31.md).

## Limitations and next decision

The synthetic data reuse fixed recipes and scored package metadata, not measured reader behavior. The adapter receives closed intervals, whereas live sessions and SQLite summary reload can differ. Navigation intent, interruptions, word counts and future visits are not independently observed. An unbiased production evaluation needs an independently designed dataset with consented real outcomes, a defined independent grading process, and tests through live recording and reload paths. The fixed candidate remains experimental; no production weights were changed.
