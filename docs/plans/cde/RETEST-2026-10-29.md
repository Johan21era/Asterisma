- **Date:** 2026-10-29
- **Formula:** `asterisma-difficulty-formula@0.3` (ADF v0.3)
- **Corpus:** `asterisma new testing suite`, 149 directory-shaped EPUB packages
- **Governing plan:** `oct-december plans.md`, §12 (evaluation dataset), §13

## 1. What was actually run

`tools/cde/cde_sheet.py` was written for this retest because the existing
`cde_run.py calibrate` cannot serve it: calibration deliberately skips
`dup_of` entries, and a retest has the opposite obligation — show that every
one of the 149 packages was scored, and prove the 14 copies matched their host
rather than assuming it.

```bash
python3 tools/cde/cde_sheet.py \
  --corpus "asterisma new testing suite" \
  --queue docs/audits/evidence/cde-phase1-engine-output-2026-10-29.json \
  --reference tools/cde/config/reference-v3.json \
  --features-out docs/audits/evidence/adf-149-features-2026-10-29.json \
  --out-json docs/audits/evidence/adf-149-scores-2026-10-29.json \
  --out-md docs/audits/evidence/adf-149-sheet-2026-10-29.md
# exit 0 on both runs; elapsed 46.29 s and 45.80 s
```

The scores file is byte-reproducible: two consecutive runs produced identical
bytes (`sha256 907b4f19bb70ae62ac7534ec8ce5f8c9c4456397dc48df1b0df3910ca6416394`).
Wall-clock time is printed, never stored — an artifact that embeds its own runtime
cannot be compared against a rerun.

| Packages scored | **149** |
| Insufficient evidence | 0 |
| Extraction failures | 0 |
| Distinct content digests | **135** |
| Duplicate groups | 14 |

Duplicate identity is a digest fact, not a filename convention: each package —
zip or unzipped tree — is hashed, and groups are formed from the hashes. All 14
copies independently scored to the same `D` and the same six dimension
percentiles as their host. The duplicate test therefore passes by computation,
not by being skipped.

Band distribution over the 149 packages:

| Light | Moderate | Demanding | Heavy | Very heavy |
|---:|---:|---:|---:|---:|
| 27 | 29 | 29 | 33 | 31 |

The bands are corpus quintiles of the 135-book reference. They are relative, not
absolute: `Very heavy` means "top fifth of these 135 books", not "hard to read".

## 2. Why this is not an accuracy test

The governing plan settles it before any grading starts:

> "Human reviewers cannot establish the actual reading time of an individual
> merely by looking at a document. Their estimates are judgments, not
> automatically ground truth." — §15.2

> "Use manual review to improve content-quality assessment and identify
> suspicious outputs. Use observed outcomes to evaluate actual reading-time
> prediction accuracy." — §15.3

ADF predicts *text demand*, not minutes. The only quantity that could validate
it is a set of observed reading sessions over these same books, and there is no
such set. §12.1 forbids substituting generated or judged labels for one.

So grading here answers a narrower question: **does the band ADF assigns match
what a careful reader says the prose demands, and when it does not, is the error
directional?** A directional error that repeats is a real defect even without a
ground-truth time.

---

## 3. Method

- Batch selected **by SHA-256 of the filename**, not by score, so the sample
  cannot be steered toward books the model already handles well.
- Five calibration books of known relative difficulty were graded first and
  ordered correctly (children's < commercial thriller < literary < translated
  19th-century < digressive Russian), so the grader was demonstrably not
  inverted before the batch began.
- The worksheet carries no `D`, band or dimensions. Verdicts were recorded
  before the score key was opened.
- 16 distinct books graded; `CANNOT_JUDGE` was never needed.

**The error is directional and grows with the band.** One book was under-called,

label saying "hardest fifth" about books the grader put in the middle. That is
precisely where a reader would use the label to decide whether to start.

## 5. Three diagnosed failures

Percentiles are against the frozen reference; `contrib` is `weight × percentile`,
so the six sum to `D`.

### 5.1 `Live by Night` — Dennis Lehane, crime novel. `D = 0.6917`, band `Very heavy`. Graded `Moderate` (−3).

| Dimension | Percentile | Contribution |
|---|---:|---:|
| People / things | 0.900 | 0.150 |
| Dialogue | 0.850 | 0.142 |
| Continuity | 0.700 | 0.117 |
| Lexical | 0.680 | 0.113 |
| Syntax | 0.650 | 0.108 |
| Density | 0.370 | 0.062 |

Lehane is not syntactically hard (Syntax 0.65, Density 0.37) and his vocabulary
is contemporary (Lexical 0.68). The book is pushed to the top band by **cast
size and dialogue volume**. A crime novel with many named characters and long
spoken exchanges looks, to this formula, like a hard book.

### 5.2 `The Beginning After the End, Book 10` — progression fantasy. `D = 0.655`, band `Very heavy`. Graded `Light` (−4, the worst single error).

| Dimension | Percentile | Contribution |
|---|---:|---:|
| Density | 0.960 | 0.160 |
| Dialogue | 0.700 | 0.117 |
| Continuity | 0.680 | 0.113 |
| Lexical | 0.670 | 0.112 |
| Syntax | 0.610 | 0.102 |
| People / things | 0.310 | 0.052 |

Information density at the 96th percentile, on prose that is plain action
narration. This is the failure mode that matters most for a product: a reader
who is told this light serial fantasy is in the top fifth will not believe the
number again.

### 5.3 `Fire and Blood` — GRRM, pseudo-chronicle. `D = 0.7583`, band `Very heavy`. Graded `Demanding` (−2).

| Dimension | Percentile | Contribution |
|---|---:|---:|
| People / things | 1.000 | 0.167 |
| Syntax | 0.930 | 0.155 |
| Density | 0.810 | 0.135 |
| Continuity | 0.800 | 0.133 |
| Lexical | 0.730 | 0.122 |
| Dialogue | 0.280 | 0.047 |

Every axis except dialogue is near the top, and `People / things` is at the
ceiling. The book is a chronicle with hundreds of names and no protagonist
continuity — which the formula reads as maximal processing demand. It is dense
in *reference*, but a reader is not holding a plot in working memory; that is a
different kind of load, and the formula has no axis for the difference.

### 5.4 The case that worked, for contrast

`The Brothers Karamazov`, `D = 0.5833`, band `Heavy`, graded `Heavy` (0): Syntax
0.95, Continuity 0.90, Lexical 0.84, Dialogue only 0.43. The formula calls this
book hard for the reasons a reader would give. The same total was reached by
`Live by Night` from entirely different axes — the aggregate hides which.

## 6. A within-series instability the aggregate hides

One series, one author, same style — `The Beginning After the End`:

| Book | `D` | Band |
|---|---:|---|
| 3 | 0.355 | Light |
| 5 | 0.512 | Demanding |
| 2 | 0.515 | Demanding |
| 12 | 0.567 | Heavy |
| 6 | 0.575 | Heavy |
| 10 | 0.655 | Very heavy |
| 7 | 0.670 | Very heavy |

A 0.315 spread across one continuous series is most of the scale. Either these
books genuinely differ that much in demand, or the score is tracking subject
matter and sampling rather than prose difficulty. No claim is made about which;
it is a testable question and a suspicious result either way.

## 7. Self-consistency: measured, and not usable

Pass B re-graded the same 16 books from a different window.

| Measure | Value |
|---|---:|
| Paired rows | 16 |
| Agreement | **1.00** |
| Cohen's κ | **1.00** |

**This number must not be cited as reliability.** Both passes were made by the
same grader within the same session, and the band call was remembered. κ = 1.00
measures that the grader's notes were stable, not that the verdicts are
reproducible. `GRADING.md` §4 requires the passes to be separated by at least a
day or an intervening task; that requirement was not met, so the result is
recorded as **inadmissible**, not as evidence of consistency.

The previous pass's honest figure was 13/20 (65%) self-consistency. Nothing in
this run improves on that, and no consistency claim replaces it.

## 8. What this does and does not establish

**Established (byte-level):**

- 149 packages, 135 distinct works, 14 byte-identical copies.
- All 149 scored with zero failures; every copy matched its host exactly.
- In a 16-book blind sample: 5 over-calls beyond one band, 1 under-call of one
  band, mean error −0.875 bands, concentrated in the top two bands.
- Three specific books are over-called for identifiable, reported reasons.

**Not established:**

- That ADF is accurate, in either direction, for the corpus as a whole.
- That the 16-book sample generalises to the other 133. It was chosen by hash,
  not by stratification, so it is unbiased in selection but small.
- Any reliability figure. The one measured is inadmissible (§7).
- Anything about reading *time*. No session data exists for these books.

**Why this is still worth having:** a one-sided error at the top of the scale is
a defect a product would feel. It is now located, explained for three books, and
reproducible — which is more than an accuracy percentage computed against
invented labels would have given.

---

## 9. Consequence for wiring

ADF is **not** wired into the app. This retest does not validate it for
reading-time estimation. The older `ReadingDifficultyProfile.difficultyMultiplier`
is used elsewhere in the app, but the main `EstimationEngine` book, chapter and
page estimates use measured page pace or a fallback without multiplying it by
that profile. Whether ADF improves reading-time prediction remains untested.

The honest boundary until the over-call is fixed and the sample is larger:

| Surface | Status |
|---|---|
| `tools/cde/cde_sheet.py` → JSON with `formula`, `score`, `band`, `interval`, dimensions | **wired** (any consumer can read it) |
| Developer inspection of a book's six axes and their contributions | available from the same JSON |
| Experimental reader-time comparison | `tools/cde/cde_personal.py` consumes score JSON and separately supplied measured sessions; it is not connected to the app. |
| User-facing reading-time estimates | **not wired, deliberately** |
| Book-detail difficulty label | **not wired, deliberately** |

Wiring it to a label before the top-band bias is fixed would teach the owner's
own reader to distrust the number, which is the one failure this project cannot
afford twice.

## 10. Next actions, in order

1. **Fix the top-band over-call.** The three diagnoses point at `People / things`
   (cast size) and `I` density rewarding crowded genre fiction. Candidate change:
   make `G` count *distinct entities per unit of continuity* rather than raw
   entity count, and test whether the Heavy/Very-heavy bias shrinks on the same
   16 books before touching anything else.
2. **Grade the remaining 133** with the worksheet already built, two independent
   passes per `GRADING.md` §4, by a reader who did not write the model.
3. **Re-run this file's §4 table** after (1) and (2). The comparison is only
   meaningful between two formula versions graded by the same procedure.
4. **Only then** consider the Swift port and the estimation-engine wiring.

The experimental reader-time comparison does not establish which model is more
accurate: it still needs observed sessions with measured words and active time.
It keeps the current ADF unchanged and makes no automatic app integration.
